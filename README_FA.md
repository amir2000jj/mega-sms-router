# Mega SMS Router (MSR) — راهنمای فارسی

[English README](README.md)

برنامه‌ی اندروید (Kotlin + Jetpack Compose) که پیامک‌های **فرستنده‌های تأییدشده‌ی شما** را دریافت می‌کند، کد را استخراج می‌کند و به APIهایی که **خودتان** تعریف کرده‌اید می‌فرستد.
Package: `com.megasmsrouter` · minSdk 26 (Android 8.0) · targetSdk 35 · version 1.0.0

## وضعیت (صادقانه)
- این سورس در محیطی نوشته شد که JDK کامل، Gradle، Android SDK و اینترنت نداشت. **هنوز کامپایل، تست یا روی گوشی اجرا نشده است.**
- ممکن است در اولین build چند خطای کوچک کامپایل ظاهر شود؛ متن خطا را بفرستید تا رفع شود.
- APK امضاشده با کلید شخصی وجود ندارد. APK دیباگ با کلید دیباگ خودکار امضا می‌شود.

## گرفتن APK بدون Android Studio (روش پیشنهادی: GitHub Actions)
1. یک حساب GitHub بسازید و یک repository خصوصی جدید.
2. تمام فایل‌های این پروژه (از جمله پوشه‌ی `.github`) را در آن آپلود کنید (Add file → Upload files).
3. به تب **Actions** بروید → workflow به نام *Build MSR APK* → **Run workflow** (یا خودکار با push اجرا می‌شود).
4. پس از پایان، در صفحه‌ی همان اجرا بخش **Artifacts** فایل `msr-debug-apk` را دانلود کنید (داخلش `app-debug.apk` و `apk-info.txt`).
5. APK را به گوشی منتقل و نصب کنید (نصب از منبع ناشناس را برای همان فایل‌منیجر مجاز کنید).

Workflow این کارها را می‌کند: `assembleDebug` (اگر خطا بدهد APK ساخته نمی‌شود)، سپس تست‌های واحد و lint (شکست آن‌ها مانع APK نمی‌شود)، سپس بررسی package/SDK/امضا با aapt2 و apksigner.

### روش جایگزین: خط فرمان (بدون Android Studio)
JDK 17 + Android command-line tools + Gradle 8.9 نصب کنید، سپس `gradle assembleDebug` (خروجی: `app/build/outputs/apk/debug/app-debug.apk`). حجم SDK حدود ۲–۴ گیگابایت است.

## نصب و استفاده
1. نصب APK و یک‌بار باز کردن برنامه (لازم است تا اندروید گیرنده‌ی پیامک را فعال کند).
2. در صفحه‌ی خانه مجوز **دریافت پیامک** را بدهید.
3. در «مقصدها» یک API بسازید (URL با https، متد، هدرها، احراز هویت، الگوی بدنه) و با «تست» بررسی کنید.
4. در «قوانین» فرستنده(های) مجاز، کلمات کلیدی/regex و مقصدها را انتخاب کنید. با «تست پیامک نمونه» بدون ارسال پیامک واقعی آزمایش کنید.
5. در خانه «فعال‌سازی ارسال» را بزنید. تا آن لحظه (پیش‌فرض) هیچ داده‌ای ارسال نمی‌شود.

## متغیرها
`{{code}} {{sender}} {{message}} {{timestamp}} {{destination_id}} {{message_id}}`
در JSON فقط داخل مقدارهای رشته‌ای جایگزین می‌شوند و بدنه با پارس/سریال‌سازی ساخته می‌شود (نه چسباندن رشته)، پس نقل‌قول و خط جدید پیامک JSON را خراب نمی‌کند. برای GET، قالب Form به پارامتر کوئری تبدیل می‌شود.

## مجوزها
`RECEIVE_SMS` (دریافت پیامک)، `INTERNET` (ارسال درخواست). هیچ مجوز دیگری ندارد. `READ_SMS` (خواندن صندوق) ندارد.

## امنیت و حریم خصوصی
- ارسال پیش‌فرض خاموش؛ قانون «همه‌ی پیامک‌ها» وجود ندارد؛ فقط فرستنده‌ی صریح + یافتن کد.
- HTTPS اجباری مگر استثنای HTTP برای همان مقصد روشن شود (هشدار نمایش داده می‌شود). اعتبارسنجی TLS هرگز غیرفعال نمی‌شود.
- هدرها، توکن‌ها و رمزها با AES-256-GCM و کلید Android Keystore رمز می‌شوند. روی دستگاه روت‌شده یا آلوده محافظت کامل نیست.
- تاریخچه فقط زمان، مقصد، متد، میزبان، کد وضعیت، مدت و تعداد تلاش را نگه می‌دارد (بدون متن پیامک/کد/هدر).
- پیامکی که با هیچ قانون فعالی مطابقت نکند هیچ اثری ذخیره نمی‌کند. فقط فیلدهای استفاده‌شده در الگوی هر مقصد در صف (رمزنگاری‌شده) می‌ماند و بعد از پایان حذف می‌شود.
- بدون تله‌متری و بدون سرور سازنده. حذف همه‌ی داده‌ها از «راهنما» ممکن است.

## معماری
`sms/` گیرنده (سبک، goAsync با timeout ۸ ثانیه) و پردازشگر (تطبیق، حذف تکراری، صف) · `domain/` پارس، مسیریابی، اعتبارسنجی · `network/` ساخت درخواست و OkHttp · `background/` WorkManager (قید اینترنت، backoff نمایی) · `data/` Room · `security/` Keystore · `ui/` Compose.
گیرنده‌ی پیامک و ارسال HTTP دو مسئولیت جداست: گیرنده فقط کار محلی انجام می‌دهد و ارسال را WorkManager انجام می‌دهد. سرویس همیشه‌فعال (foreground) استفاده نشده است.

## تضمین ارسال
At-least-once، نه exactly-once. اگر مقصد Idempotency-Key را پشتیبانی کند و تلاش مجدد POST/PATCH روشن باشد، تکرار در سمت سرور قابل حذف است. تلاش مجدد فقط برای خطاهای موقت و محدود با تأخیر نمایی است.

## محدودیت‌ها
- Force stop یا محدودیت‌های سازنده (باتری) می‌توانند دریافت را متوقف کنند؛ ارسال بدون وقفه تضمین نمی‌شود.
- انتخاب targetSdk 35 برای رفتار فعلی اندروید است و برای دور زدن محدودیتی پایین نیامده است.
- توزیع در Google Play به تأیید سیاست مجوزهای پیامک نیاز دارد؛ نسخه‌ی فعلی برای نصب مستقیم و تست توسعه‌دهنده است.
- رابط فقط فارسی (RTL) است؛ رشته‌ها در `strings.xml` هستند و افزودن `values-en` ممکن است.

## تست‌ها
- `app/src/test`: استخراج کد (فارسی/عربی/انگلیسی)، regex، فرستنده، مسیریابی و تداخل قوانین، JSON و escape، هدر، URL، retry، حذف تکراری، پیامک چندبخشی، و تست شبکه با MockWebServer (۴۰۰/۴۰۱/۴۰۳/۴۲۹/۵۰۰، timeout، آفلاین، متدها، Form/JSON/Text، چند مقصد مستقل). اجرا: `gradle testDebugUnitTest`.
- `app/src/androidTest`: پردازشگر با Room (نیازمند امولاتور/گوشی؛ در CI اجرا نمی‌شود).
- تست روی دستگاه واقعی (دریافت پیامک واقعی، مجوز زمان اجرا، باتری، راه‌اندازی مجدد) باید دستی انجام شود و تاکنون انجام نشده است.
